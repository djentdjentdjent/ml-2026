# Отчёт за 16.11–23.11.2026

**Проект:** «Receipts»  
**Команда:** 12  
**Авторы:** Мартынов Александр, Сороколетов Денис

## 1. Цель работы за период

Улучшить точность уже работающего локального конвейера распознавания российских чеков и сохранить простой запуск через API и интерфейс.

## 2. Что было сделано

- Настроили пороги классификатора товарных строк и замены названия по каталогу на validation. Для новой настройки выбраны порог строки 0,75 и порог каталожного совпадения 40; она отсекает больше сомнительных строк.
- Применили эти пороги по умолчанию в предикторе, который использует локальное приложение.
- Повторно оценили предсказания на 115 чеках validation, используя сохранённые результаты PP-OCRv5/PP-OCRv6 и ту же разметку, что в предыдущей оценке.
- Сохранили метрики и предсказания для воспроизведения: [точные метрики](../../ml/reports/ocr_v6_tuned_2026-11-23.json), [сопоставление с похожестью названия](../../ml/reports/ocr_v6_tuned_2026-11-23.fuzzy-metrics.json), [предсказания](../../ml/reports/ocr_v6_tuned_2026-11-23.jsonl).

## 3. Результаты проверки

На 379 размеченных позициях новый вариант вернул 260 позиций. Для сравнения приведён предыдущий вариант конвейера с порогами 0,5 и 60.

| Поле | Предыдущий F1 | Текущий F1 | Точные совпадения сейчас |
|---|---:|---:|---:|
| Название | 35,9% | 37,6% | 120 |
| Количество | 69,2% | 69,8% | 223 |
| Цена | 69,5% | 69,2% | 221 |
| Сумма | 71,5% | 69,8% | 223 |
| Полная строка | 26,3% | 29,4% | 94 |

Точный F1 полной строки вырос на 3,1 пп, названия — на 1,7 пункта. В абсолютном выражении полностью совпавших строк стало на три больше (94 вместо 91), а предсказаний — на 52 меньше (260 вместо 312). Точность повысилась за счёт более строгого отбора, полнота не улучшилась; для интерфейса это означает, что больше товаров может потребовать ручного добавления. При сопоставлении названий с похожестью не ниже 80% F1 названий составил 61,3%, полной строки с точными числами — 48,8%. Эти показатели относятся к автоматической разметке validation и не заменяют проверку на вручную размеченных чеках.

## 4. Текущий статус

| Компонент | Статус |
|---|---|
| PP-OCRv5 + PP-OCRv6 и классификатор строк | Запускаются локально; новые пороги дали небольшое улучшение точного извлечения позиций |
| Локальный API и React-интерфейс | Используют предиктор с обновлёнными параметрами |
| Проверка качества | Выполнена на 115 чеках validation; Test не использовался |

Прототип формирует черновик чека, который нужно проверить и при необходимости исправить вручную. До автоматического сохранения без проверки качество не доведено.
