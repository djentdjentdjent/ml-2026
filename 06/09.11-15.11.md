# Отчёт о проделанной работе за неделю (09.11–15.11.2026)

## Тема проекта

**«Технологический трекер Hacker News»** — веб-сервис аналитики и прогнозирования популярности технологий на основе постов и комментариев Hacker News.

## Кратко

На этой неделе завершили подключение оценок вовлечённости к сервису и проверили методы на отдельных контрольных данных. Зафиксирована версия словаря технологий, получены итоговые precision/recall/F1 на отложенных заголовках. Подготовлена новая разметка комментариев, повторно сравнены методы общего и аспектного тона. Word2Vec переобучен на большем корпусе; проблема вырожденной модели заголовков устранена, но bootstrap по-прежнему уступает VADER. Для IRR сохранены результаты семи вариантов расчёта и построен общий график доверительных интервалов. Независимая человеческая проверка разметки остаётся незавершённой: текущие метрики тональности получены по предварительным AI-меткам.

## Проделанная работа

### 1. Итоговая проверка словаря технологий
- Подготовлены **600 случайных заголовков**, отобранных независимо от наличия найденной технологии. Из них 200 использованы для разбора ошибок и доработки правил, 400 оставлены для итоговой проверки. Выборка не пересекается со статьями прежних наборов оценки и обучения bootstrap.
- Сохранён фиксированный каталог из **121 технологии**. Разметка выполнена с помощью ИИ без показа предсказаний классификатора; происхождение меток записано в CSV. Для заголовков без технологий каталога используется `[]`, продукты вне каталога не включаются в знаменатель recall.
- Уточнены неоднозначные паттерны `poetry`, `bundler`, `windows` и названия языков. Для неоднозначных инструментов добавлена проверка технического контекста; дополнены отдельные пропущенные названия и синонимы. Для известных ошибок добавлены положительные и отрицательные регрессионные примеры.
- Версия словаря зафиксирована до просмотра отложенной части. Сохранён контрольный отпечаток исходника; после проверки holdout правила по его результатам не менялись.
- На **400 отложенных заголовках** получены **micro precision = 0,958, recall = 0,780, F1 = 0,860**. Найдено 46 верных упоминаний, 2 ложных срабатывания и 13 пропусков. Метрики и ошибки сохранены отдельно по технологиям. В контрольной части всего 59 размеченных упоминаний, поэтому точность оценки, особенно для отдельных технологий, пока ограничена.
- Исправлен повторный запуск классификации: раньше он только добавлял связи статьи с технологией. Теперь удаляются и устаревшие совпадения, которые перестали подходить под новые правила. После синхронизации словаря пересчитаны метрики сервиса.
- **Результат.** Получена итоговая оценка на независимой от отбора классификатором выборке. Высокая precision сочетается с заметными пропусками; работу над recall нужно продолжать на новой контрольной части, не подбирая правила по уже просмотренному тесту.

### 2. Расширение разметки и повторное сравнение тональности
- Отобраны **315 новых комментариев из 241 статьи** для Linux, GPT, Python, Rust, JavaScript и Windows. Статьи не пересекаются с прежними выборками и новой проверкой заголовков. Сохранено разделение реплик с явным упоминанием технологии и без него.
- В этот набор включена собственная проза автора длиной **60–650 символов**, без обрезания полного текста реплики. Поэтому это проверка коротких комментариев, а не представительная оценка качества на всех обсуждениях HN.
- Заполнены 315 меток `label_comment` и **205 меток `label_tech`**. Общий тон и отношение к технологии размечаются отдельно; пустое поле отношения не заменяется нейтральным классом. Для неоднозначных случаев сохранены пояснения: например, критика автора статьи или стороннего приложения не переносится автоматически на язык программирования или ОС.
- **Новая разметка выполнена с помощью ИИ; человеческая проверка этого набора ещё не проведена.** При разметке не показывались оценки VADER и других сравниваемых методов. Это предварительные данные для экспериментов, а не человеческий эталон.
- Закреплено разделение по статьям: 157 комментариев в train, 78 в validation и 80 в test. Одна статья не попадает в разные части. Для отношения к технологии в тесте осталось 50 заполненных меток. Пороги и метод выбираются только на validation.
- Повторно сравнены шесть режимов: VADER по всему комментарию, VADER по предложениям с упоминанием, оконный VADER, лексиконный метод, его аспектный вариант и bootstrap. В оконном режиме исправлена подстановка общего тона при отсутствии технологии. Теперь он ищет упоминания с учётом словарных синонимов, а отсутствие упоминания считается отказом от ответа и учитывается в покрытии и F1.
- Для общего тона выбран VADER: **test macro-F1 = 0,603**. Для отношения к технологии VADER по всему комментарию дал 0,379, VADER по предложениям с упоминанием — **0,339 при покрытии 74%**, оконный вариант — 0,300. Более высокая оценка общего VADER сама по себе не означает, что он правильно выделяет объект отношения.
- Для общего VADER и VADER по предложениям с упоминанием пороги подобраны раздельно; в этом эксперименте оба оказались равны **0,05**. В предрасчёт добавлен отдельный параметр аспектного порога. Это настройки подготовленной экспериментальной базы, а не изменение порога по умолчанию для всех запусков.
- **Результат.** Для общего тона сохранён базовый VADER. Качество отношения к технологии пока недостаточно для уверенных выводов. Метрики нового набора нельзя напрямую сравнивать с прошлым пилотом: изменились состав и ограничения выборки. Пункт плана о независимой человеческой разметке остаётся открытым.

### 3. Подключение вовлечённости к предрасчёту, API и интерфейсу
- Расчёт IRR включён в обычный предрасчёт и больше не требует обязательного наличия модели Word2Vec заголовков. Базовый вариант использует NB2, индикаторы технологий и контроли формата статьи, без взаимодействий. Это позволяет получать оценки независимо от качества эмбеддингов.
- Сохранена полная база из **93 713 статей за апрель–август 2024 года**, включая статьи без обнаруженных технологий. Для включения технологии в регрессию по умолчанию требуется не менее **30 статей**. Число комментариев берётся из метаданных HN.
- Перед публикацией проверяются сходимость модели, конечность коэффициента и интервала, положительность и порядок границ. Некорректные значения не превращаются в численные результаты API.
- Для каждой технологии сохраняются IRR, 95% доверительный интервал, p-value, число статей в расчёте и состояние оценки. Различаются доступный результат, нехватка данных, невозможность получить корректную отдельную оценку, ошибка модели и отсутствие предрасчёта.
- На подготовленной базе допустимые оценки получены для **43 технологий**; для остальных 78 возвращается состояние «мало данных». Наличие допустимой оценки не означает статистической значимости: флаг значимости проверяет, исключает ли интервал единицу.
- На странице технологии добавлены отдельные пояснения для нехватки данных и ошибки расчёта. При интервале, включающем 1, показывается отсутствие убедительной связи, без утверждения о росте числа комментариев. Формулировки описывают связь при фиксированных остальных признаках модели и не подают её как причинное влияние.
- Изменения применены в основной проект. Модели, готовая база и результаты сохранены в `artifacts/study`; крупные артефакты исключены из Git. Проверены API на готовой базе, **383 Python-теста, 31 тест фронтенда, проверка типов, сборка и Ruff**. Состояния ошибки модели и незначимой оценки покрыты тестами.
- **Результат.** Оценки вовлечённости доступны через сервис вместе с интервалами и понятной причиной отсутствия результата. Для просмотра подготовленных данных API должен использовать новую базу `artifacts/study/hn.db`.

### 4. Визуализация IRR и сравнение временных отрезков
- Сохранены результаты **семи вариантов расчёта**: NB2 на полном периоде, на ранней и поздней хронологических половинах, с минимумом 60 и 100 статей на технологию, без контролей формата и Poisson с робастными ошибками. Все семь моделей сошлись.
- Половины сформированы по времени и числу статей: первая охватывает 11 апреля — 6 июня, вторая — 6 июня — 6 августа 2024 года. Их размеры составляют 46 856 и 46 857 статей. Для каждого варианта сохранены состав признаков, частоты технологий и диагностика модели.
- Построена сводная визуализация IRR с **95% доверительными интервалами** для полного периода и обеих половин. Используется логарифмическая шкала и линия IRR = 1; на графике указаны даты. Результат сохранён в PNG и SVG.
- Например, для Windows на полном периоде получен **IRR = 2,19, интервал 1,52–3,15**. В ранней половине оценка составляет 1,63 с интервалом 0,99–2,68, в поздней — 2,84 с интервалом 1,67–4,81. Направление связи сохраняется, но значимость на отдельных отрезках различается. Это не является отдельным доказательством изменения эффекта во времени.
- Для Rust на полном периоде получен **IRR = 0,97, интервал 0,69–1,37**. Интервал включает единицу; оснований говорить об убедительной связи с увеличением или уменьшением числа комментариев нет.
- **Результат.** Сравнение больше не ограничивается одной таблицей коэффициентов. График показывает неопределённость и чувствительность к периоду, а дополнительные варианты позволяют проверить зависимость оценки от частотного порога и контролей.

### 5. Переобучение Word2Vec и проверка bootstrap
- Модель заголовков обучена на **92 683 заголовках**, модель контекста — на **73 883 комментариях**. Из обучения исключены 1 030 статей, относящихся к текущим и прежним наборам оценки. Весь миллион собранных комментариев в это обучение не входил.
- Использованы Skip-gram, векторы размерности 50, окно 5, минимальная частота 2 и 20 эпох. Для воспроизводимости зафиксированы seed = 42, один рабочий поток, параметры и состав исключений. В этом эксперименте тексты токенизировались без лемматизации.
- Словарь модели заголовков содержит 25 887 токенов и 93 технологии, модели контекста — 33 716 токенов и 102 технологии. Средняя близость между технологиями составляет **0,467 и 0,380** соответственно. Обе модели проходят проверку на вырожденность; прежняя проблема почти совпадающих векторов заголовков не воспроизводится.
- На заранее заданных проверочных парах обе модели дали **hit@10 = 0,85**; MRR составил 0,506 для заголовков и 0,564 для контекста. Это небольшая диагностическая проверка, а не доказательство качества всех соседей.
- После проверки эмбеддингов повторно оценён bootstrap. Для получения обучающих псевдометок использована отдельная неразмеченная выборка из 3 000 строк, без пересечения со статьями оценки. На тесте получены **macro-F1 = 0,372 для общего тона и 0,199 для отношения к технологии**.
- В готовый предрасчёт записаны метрики 121 технологии, **1 020 связей Word2Vec**, частые слова и 421 пример комментариев. Модели и параметры обучения сохранены для повторного использования.
- **Результат.** Увеличение корпуса устранило вырожденность Word2Vec, но не обеспечило преимущество bootstrap над VADER. Bootstrap оставлен экспериментальным методом; для следующего шага нужно разбирать качество псевдометок и представления текста, а не только увеличивать число эпох.

## Проблемы и риски
- Независимая человеческая проверка новой разметки не завершена. AI-метки могут содержать систематические ошибки, поэтому текущие значения F1 нельзя выдавать за качество относительно человеческого эталона.
- В тесте отношения к технологии всего 50 размеченных примеров, а сам набор ограничен короткими репликами и шестью технологиями. Особенно слабо проверены длинные комментарии и отношение без явного названия объекта.
- В контрольной выборке заголовков только 59 упоминаний технологий. Для многих отдельных технологий данных недостаточно; высокая precision не отменяет пропуски и ограничения каталога.
- Словарные методы тональности по-прежнему плохо различают объекты сравнения, техническую критику и сарказм. Невырожденные эмбеддинги сами по себе эту проблему не решают.
- IRR остаётся наблюдаемой связью. Не устранены все различия тематики, видимости статей и аудитории. Интервалы условны на оценке дисперсии и отборе признаков; поправка на множество проверок технологий не применялась.
- Подготовленная база историческая, за апрель–август 2024 года. Публичный деплой, обновление данных по расписанию и прогноз интереса к технологиям пока не завершены.

## Планы на следующую неделю
- Провести независимую человеческую проверку части новой разметки, расширить набор отношений к технологии длинными репликами и примерами без явного упоминания. Сохранить происхождение меток и отдельный контрольный набор по статьям.
- Проверить обучаемый классификатор отношения к технологии и сравнить его с VADER. Отдельно разобрать ошибки bootstrap и распределение его псевдометок; параметры выбирать без использования итогового теста.
- Продолжить работу над пропусками словаря на рабочей части данных. Для следующей версии правил подготовить новую отложенную проверку, не используя уже просмотренные 400 заголовков для подбора.
- Проверить влияние календарного периода и множественных сравнений на выводы IRR; дополнить пояснения к результатам на странице технологии.
- Расширить проверку соседей Word2Vec за пределы небольшого набора пар, особенно для редких технологий и неудачных соседств.
- Подготовить недельные ряды доли упоминаний технологий и начать проверку простых прогнозов интереса с хронологическим разделением данных.
