# Отчёт о проделанной работе за неделю (16.11–22.11.2026)

## Тема проекта

**«Технологический трекер Hacker News»** — веб-сервис аналитики и прогнозирования популярности технологий на основе постов и комментариев Hacker News.

*Дата подготовки — 23 ноября. Итоги этапа приведены с учётом доработок, повторных экспериментов и проверок, выполненных 23 ноября при подготовке отчёта.*

## Кратко

Добавлена первая прогнозная часть: недельные ряды доли упоминаний технологий, сравнение простых методов с Ridge-регрессией и показ результатов в сервисе. Для тональности проверен обучаемый классификатор TF-IDF/SVM; на текущей выборке он уступил VADER. Разбор bootstrap выявил отсутствие нейтрального класса среди обучающих псевдометок. Оценки вовлечённости дополнены календарными контролями в отдельном эксперименте и поправкой на множественные проверки. Расширена диагностика Word2Vec, подготовлены новые данные для независимой разметки. В интерфейс добавлены сравнение технологий, карта и фильтр категорий. Для презентации выбран локальный запуск; публичный хостинг в текущий объём не входит. Человеческая проверка разметки остаётся незавершённой.

## Проделанная работа

### 1. Недельные ряды и первый прогноз интереса

- На исторической базе из **93 713 статей за апрель–август 2024 года** подготовлены недельные ряды доли упоминаний. Знаменатель — все живые статьи с заголовком, включая статьи без найденных технологий. Такая доля позволяет учитывать изменение общего объёма публикаций HN.
- Используются только полные недели с понедельника по воскресенье, по UTC. Неполные крайние недели исключаются. Неделя без статей не превращается в нулевой интерес: отсутствие данных делает ряд непригодным для текущего эксперимента.
- Сравниваются семь вариантов: последнее значение, среднее за четыре недели, значение четыре недели назад и Ridge-регрессия с четырьмя значениями регуляризации. Признаки регрессии строятся из предыдущих долей и их изменений; нормализация обучается только на доступной к моменту прогноза истории.
- Разделение хронологическое: на текущем наборе **9 недель первоначального обучения, 3 недели validation и 4 недели test**. Метод выбирается по средней абсолютной ошибке на validation и фиксируется до test. На каждом тестовом шаге прогнозируется одна следующая неделя, затем история пополняется уже наблюдённым значением. Это не прогноз сразу на четыре недели вперёд.
- Для допуска нужны не менее **16 полных недель** и **30 упоминаний в первоначальной обучающей части**. Условия выполнены для **38 технологий**. Для **15 из 38** выбранный метод дал меньшую ошибку на test, чем прогноз «как на прошлой неделе». Для остальных преимущество не получено.
- Добавлены таблица предрасчёта, эндпоинт `/api/techs/{key}/forecast` и блок на странице технологии. Показываются доля, период данных, тестовая ошибка и результат сравнения с базовым методом. Архивный характер оценки обозначен явно: последняя полная неделя заканчивается **4 августа 2024 года**, прогноз относится к неделе с **5 августа**.
- **Результат.** Прогнозная часть реализована и проверена с хронологическим разделением. Четырёх тестовых недель недостаточно для вывода об устойчивом преимуществе; доверительные интервалы прогноза пока не рассчитаны.

### 2. Обучаемый классификатор тональности и диагностика bootstrap

- Реализован эксперимент **TF-IDF слов и символьных n-грамм + LinearSVC**. Для отношения к технологии во вход включаются её название, заголовок статьи и текст комментария. Словарь признаков и IDF обучаются только на train; коэффициент регуляризации выбирается на validation.
- Использована прежняя выборка из 315 коротких комментариев с закреплённым разделением по статьям. Для общего тона в train/validation/test входят 157/78/80 строк; для отношения к технологии с заполненной меткой — 108/47/50. Пустые аспектные метки не заменяются нейтральным классом.
- Обучаемый метод сопоставлен с VADER, порог которого также выбирается только на validation:

| Метод | Test macro-F1: общий тон | Test macro-F1: отношение к технологии |
|---|---:|---:|
| TF-IDF + LinearSVC | 0,404 | 0,324 |
| VADER по всему комментарию | 0,603 | 0,379 |

- На этом наборе SVM уступил базовому VADER и не заменяет его в сервисе. Сравнение по второй колонке не означает, что общий VADER корректно определяет объект отношения: эта проблема остаётся открытой. Все метрики получены относительно **AI-разметки**, а не независимого человеческого эталона.
- Для bootstrap отдельно разобрана выборка из **3 000 обучающих строк**, не пересекающаяся по статьям с текущей оценкой. Среди всех псевдометок: 1 326 положительных, 1 136 нейтральных и 538 отрицательных. После отбора по модулю уверенности остаются **600 строк: 449 положительных, 151 отрицательная и ни одной нейтральной**.
- Такой отбор исключает нейтральный класс из обучения, поэтому полученный классификатор не может его предсказывать. Нулевые векторы найдены лишь у **6 из 3 000 строк**: слабый результат нельзя объяснить только отсутствием представления текста. Балансировка весов двух оставшихся классов не возвращает третий класс.
- **Результат.** Проверен обучаемый подход и выявлено конкретное ограничение bootstrap. Улучшение качества не заявляется; дальнейшая работа требует более надёжных меток и пересмотра отбора псевдометок.

### 3. Календарные факторы и множественные проверки IRR

- К семи прежним спецификациям добавлена NB2-модель с календарными контролями: **месяц, день недели и циклическое представление часа публикации по UTC**. Контроли формата статьи сохранены. Всего рассчитаны восемь вариантов; все модели сошлись.
- Для Windows в календарном варианте получен **IRR = 2,216**, 95% интервал **[1,543; 3,184]**. Направление связи близко к основной модели, но это не устраняет возможное смешение по теме публикации, её видимости и аудитории.
- Добавлена поправка **Бенджамини — Хохберга (BH)** к p-value коэффициентов технологий. Контроли формата, календарные признаки и взаимодействия не включаются в это семейство проверок. В основной полной модели при **FDR 5%** значимость сохраняет **1 технология вместо 5**, значимых по отдельным p-value.
- Для Windows BH q-value основной модели составляет около **0,000980**, календарного варианта — **0,000712**. При этом результаты зависят от спецификации: в варианте Poisson с робастными ошибками q-value Windows составляет около 0,206. Отдельный удачный вариант не рассматривается как доказательство устойчивости всех выводов.
- В предрасчёт, API и интерфейс добавлены `qval` и `significant_adjusted`. Отдельный 95% доверительный интервал и значимость после множественной проверки показываются как разные характеристики. Календарный вариант остаётся отдельным сравнительным экспериментом; в сервисе сохраняется основная спецификация.
- **Результат.** Выводы стали осторожнее: исключение единицы из отдельного интервала больше не подаётся как достаточное основание для значимости при проверке множества технологий. Интервалы остаются условными на оценке дисперсии и отборе признаков и не являются одновременными интервалами для всего каталога.

### 4. Расширенная проверка соседей Word2Vec

- Диагностика расширена с небольшого набора проверочных пар на **все 102 технологии**, представленные в модели контекста. Сохранены ближайшие соседи, частоты токенов и список 19 технологий каталога, отсутствующих в словаре модели.
- Как дополнительный диагностический показатель рассчитана доля соседей из общей категории. Для **31 редкой технологии** с частотой токена меньше 20 она составила **0,248**, для остальных **71 технологии — 0,597**. Этот показатель основан на категориях каталога и не заменяет человеческую оценку смысловой релевантности.
- Подготовлен CSV для проверки соседей человеком: технология, сосед, ранг, близость, частота и пустые поля для решения и пояснения проверяющего.
- Стандартные настройки обучения согласованы с ранее успешным экспериментом: **50 измерений, 20 эпох, seed = 42, один поток**. Имена моделей в Bash/BAT обновлены. Для формальных экспериментов сохранён отдельный сценарий обучения с исключением оценочных статей; обычный корпус без идентификаторов не позволяет автоматически выполнить такое исключение.
- **Результат.** Слабые места редких технологий теперь видны в общей диагностике. Новое улучшение качества эмбеддингов не заявляется: выполнен аудит существующих моделей и обновлены настройки воспроизводимости.

### 5. Новые выборки и подготовка человеческой проверки

- Подготовлены **600 новых случайных заголовков**: 200 development и 400 holdout. Исключены статьи прежних оценок и обучения bootstrap. Для следующей версии словаря сначала должна использоваться рабочая часть, а итоговая контрольная часть — только после фиксации правил.
- Дополнительно отобран **101 длинный комментарий из 89 статей**, длина собственной прозы — **651–5000 символов**. Сохранены группы с явным упоминанием технологии и без него; разделение train/validation/test закреплено по статьям. Набор не пересекается с новой выборкой заголовков. Всего из отбора исключены **1 760 статей** предыдущих наборов.
- Метки новых наборов оставлены пустыми. Человеческая разметка не подменяется автоматически сгенерированными ответами. Замороженный словарь и прежние 400 контрольных заголовков не использованы для подбора новых правил; повышение recall пока не заявляется.
- Для прежних 315 комментариев подготовлен слепой лист без AI-меток, модельных оценок и подсказок. Импорт проверяет соответствие исходному тексту, технологии и split, требует имя проверяющего и дату. В человеческий набор включаются только завершённые строки; пустое отношение к технологии сохраняется пустым.
- **Результат.** Подготовлены данные и процедура независимой проверки, включая длинные реплики. Сама человеческая проверка ещё не выполнена.

### 6. Интерфейс и локальная демонстрация

- Добавлено сравнение двух-трёх технологий: число статей, доля упоминаний, число комментариев, общий и аспектный тон, IRR с интервалом. Значения без достаточных оснований не показываются как надёжный результат.
- Добавлена интерактивная карта по сохранённым координатам t-SNE с переходом на страницу технологии и фильтром категорий. На карте показываются технологии минимум с 30 статьями; каталог категории доступен списком. Поясняется, что расстояния между далёкими группами t-SNE нельзя трактовать как точную меру связи.
- Для презентации выбран **локальный показ**. Один процесс Uvicorn обслуживает API и собранный React-интерфейс; отдельный Node-сервер во время демонстрации не нужен. Добавлены проверка наличия данных и сборки, команда запуска и PowerShell-обёртка. Публичный хостинг, домен и серверный деплой исключены из текущего объёма.
- Подготовлен сценарий ограниченного инкрементального обновления: новые ID и повторная загрузка части недавних элементов, переиспользование моделей, пересчёт метрик и прогнозов. При ошибках скачивания пакет останавливается до импорта. Массовая актуализация исторической базы до текущей даты не проводилась; обновление не запускается автоматически при показе.
- **Результат.** Основные результаты можно показать локально на подготовленной базе, сохранив явное указание исторического периода и ограничений методов.

### 7. Проверки и воспроизводимость

- Прошли **394 Python-теста**, **34 теста компонентов фронтенда** и **24 браузерных сценария** на настольном и мобильном экране, включая проверки доступности axe. Проверка типов TypeScript, production-сборка и Ruff проходят.
- Добавлены проверки хронологического разделения прогноза, отсутствия влияния будущих значений на выбор метода, исключения неполных недель, расчёта долей с правильным знаменателем и отсутствия пересечения статей между частями разметки.
- В браузерной проверке обнаружено переполнение сетки страницы технологии на узком экране. Оно мешало переходу к соседней технологии; ширина исправлена, мобильный сценарий повторно прошёл проверку.
- Изменения, сборка и результаты экспериментов перенесены в основной проект. На его базе дополнительно проверены API, прогнозы, поправка BH и маршруты локального интерфейса. Добавлена конфигурация CI; её запуск на GitHub потребует отправки изменений в репозиторий.
- **Результат.** Реализация проверена локально, результаты и ограничения описаны в документации. Число пройденных технических тестов не рассматривается как подтверждение качества ML-моделей.

## Проблемы и риски

- Независимая человеческая разметка не завершена. Текущие метрики тональности показывают согласие с предварительными AI-метками; эталон для окончательных выводов ещё не сформирован.
- Для прогноза доступны лишь 16 полных недель и четыре тестовые точки на технологию. Нет откалиброванных интервалов и проверки на новых исторических периодах. Преимущество у 15 из 38 технологий не означает устойчивого превосходства метода.
- Обучаемый классификатор уступил VADER. Аспектная тональность по-прежнему слабо проверена на длинных репликах, сарказме, сравнениях и неявном объекте отношения.
- Отбор самых уверенных псевдометок bootstrap исключил нейтральный класс. Требуется пересмотр схемы обучения; наличие невырожденных Word2Vec-векторов само по себе не решает эту проблему.
- Календарные контроли и BH-поправка не превращают IRR в причинную оценку. Результаты чувствительны к спецификации модели; отбор признаков и оценка дисперсии остаются источниками неопределённости.
- Категориальная согласованность соседей — только прокси. Особенно ненадёжны редкие технологии; человеческая проверка соседей ещё не выполнена.
- Новые выборки словаря не размечены, поэтому улучшение precision/recall следующей версии пока нельзя измерить. Подготовленная база остаётся исторической, за апрель–август 2024 года.

## Планы на следующую неделю

- Провести независимую человеческую проверку части прежней разметки и новых длинных комментариев; сохранить автора, дату, причины расхождений и разделение по статьям.
- Пересмотреть отбор псевдометок bootstrap с учётом нейтрального класса; повторить сравнение только после фиксации процедуры и параметров на рабочей части данных.
- Разметить development-часть новых заголовков, улучшить полноту словаря, зафиксировать версию и затем провести итоговую оценку на новом holdout.
- Расширить временной охват данных, повторить прогнозный эксперимент на нескольких последовательных отрезках и оценить устойчивость выигрыша относительно базовых методов.
- Проверить соседей Word2Vec человеком, отдельно разобрать редкие технологии и отсутствующие в модели элементы каталога.
- Подготовить сценарий презентации: поиск технологии, сравнение, карта, тональность, IRR и архивный прогноз. Перед показом проверить локальный запуск и сохранить используемый снимок базы.
