# Отчёт за 09.11–15.11

**Проект:** «Распознавание окружающих звуков»  
**Команда:** 8

## 1. Цель работы за отчётный период

Подготовить воспроизводимый Docker-образ приложения, проверить полный сценарий
работы в изолированном окружении без локального Python-окружения, добавить
автоматическую проверку контейнера и подготовить конфигурацию для публикации.

## 2. Что было сделано

### 2.1. Подготовка Docker-образа

- Добавлен двухэтапный `Dockerfile` на основе Python 3.12.
- Зависимости устанавливаются строго по `uv.lock`, версия `uv` зафиксирована.
- На первом этапе создаётся Python-окружение и устанавливается проект, а в
  итоговый образ копируются только готовое окружение и обученная модель.
- Датасет ESC-50, кэши признаков, notebooks, тесты, инструменты разработки и
  сборочные утилиты в итоговый образ не включаются.
- Добавлен `.dockerignore`; размер передаваемого при сборке контекста составил
  4,34 МБ.

### 2.2. Разделение рабочих и исследовательских зависимостей

- JupyterLab, pandas и Matplotlib перенесены в отдельную группу `research`.
- Константы версии и расположения артефакта модели вынесены в независимый модуль
  `model_artifact.py`.
- Сервер и модуль прогнозирования больше не импортируют код обучения при запуске.
- В контейнер устанавливается 41 рабочая зависимость без исследовательских и
  тестовых пакетов.

### 2.3. Настройка запуска и защищённого окружения

- Сервер теперь получает адрес и порт из переменных `HOST` и `PORT`, сохраняя
  безопасные локальные значения по умолчанию.
- Итоговый процесс запускается от непривилегированного пользователя `app`.
- В `compose.yaml` корневая файловая система контейнера переведена в режим
  только для чтения.
- Для временных аудиофайлов и кэша Numba выделена временная файловая система
  размером 64 МБ.
- В образ добавлен healthcheck, обращающийся к `GET /health` без установки
  дополнительных системных утилит.

### 2.4. Автоматическая проверка контейнера

- Добавлен скрипт `scripts/check_container.sh`, который собирает образ, запускает
  контейнер и ожидает готовности модели.
- Скрипт проверяет `/health`, главную страницу и список из 50 классов.
- Для проверки полного пути автоматически создаётся односекундный WAV-файл,
  отправляется в `/predict`, после чего проверяется структура ответа и три
  результата модели.
- Временный контейнер и сгенерированные файлы удаляются автоматически.
- При ошибке перед удалением контейнера выводится его серверный журнал.

### 2.5. Публикация на Render

- Добавлен `render.yaml` с Docker-сервисом и HTTP healthcheck по адресу
  `/health`.
- Образ поддерживает назначаемый площадкой порт и не требует отдельной команды
  запуска для Render.
- Частный GitHub-репозиторий подключён к Render с доступом только к проекту
  `sound-recognition`.
- Из `render.yaml` создан Blueprint, автоматически собирающий и публикующий
  коммиты из ветки `main`.
- Коммит `8da6810` успешно собран за 1 минуту 15 секунд и опубликован на
  бесплатном экземпляре Render.
- README дополнен командами локальной проверки и постоянной ссылкой на
  опубликованное приложение.

## 4. Возникшие проблемы и принятые решения

- В защищённом контейнере первый запрос завершался ошибкой, поскольку Numba
  пыталась создать кэш внутри Python-окружения на файловой системе только для
  чтения. Кэш перенесён в `/tmp/numba`, после чего полный smoke-тест успешно
  прошёл без ослабления защиты контейнера.
- Первый вариант ожидания готовности мог принять непустой ошибочный ответ за
  успешный запуск. Добавлен отдельный флаг успешного ответа `/health` и вывод
  журнала контейнера при любой ошибке.
- Импорт модуля прогнозирования ранее приводил к загрузке исследовательских
  модулей обучения. Общие константы артефакта вынесены в лёгкий модуль, поэтому
  pandas, Matplotlib и JupyterLab больше не нужны в production-образе.
- Контейнерный движок отсутствовал в локальном окружении. Установлены Docker CLI,
  Compose, Buildx и Colima; после этого образ проверен как обычной сборкой, так и
  через команды из README.
- Бесплатный экземпляр Render может запускаться с задержкой после простоя. Это
  ограничение площадки зафиксировано в README и учитывается при подготовке
  демонстрации.
