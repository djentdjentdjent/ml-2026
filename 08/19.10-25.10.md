# Отчёт за 19.10–25.10

**Проект:** «Распознавание окружающих звуков»  
**Команда:** 8

## 1. Цель работы за отчётный период

Создать первую сквозную версию веб-приложения: предоставить страницу выбора
аудиофайла, дать пользователю возможность прослушать запись, связать интерфейс с
методом `POST /predict`, показать основной результат и три наиболее вероятных
класса, а также добавить состояние обработки и понятные сообщения об ошибках.

## 2. Что было сделано

### 2.1. Веб-страница приложения

- В FastAPI-приложение добавлен метод `GET /`, возвращающий HTML-страницу через
  шаблон Jinja2.
- Подключена раздача CSS и JavaScript из пакета приложения по пути `/static`.
- Создана адаптивная двухпанельная страница: слева расположен выбор записи, а
  справа — результаты распознавания.
- На странице отображается состояние модели, которое проверяется запросом к
  `GET /health`. После успешной проверки показано количество поддерживаемых
  классов.
- Интерфейс корректно перестраивается в одноколоночный вид на узком экране и
  учитывает системную настройку уменьшения анимации.
- Все пользовательские надписи, состояния и ошибки отображаются на русском
  языке.

### 2.2. Выбор и прослушивание аудиофайла

- Добавлен выбор файла через стандартный диалог браузера и перетаскиванием в
  область загрузки.
- Для выбранной записи показываются имя и размер файла.
- Встроенный HTML-аудиоплеер позволяет прослушать запись до отправки модели.
- Пользователь может удалить выбранный файл и выбрать другой.
- Создаваемый браузером временный URL аудиофайла освобождается при замене файла,
  его удалении и закрытии страницы.

### 2.3. Интеграция интерфейса с моделью

- JavaScript формирует запрос `multipart/form-data` и передаёт запись в
  существующий метод `POST /predict` без перезагрузки страницы.
- Во время распознавания кнопка и элементы выбора блокируются, отображаются
  индикатор и текст состояния. Это также предотвращает повторную отправку одного
  запроса.
- После ответа отдельно показываются основной результат и его уверенность.
- Ниже выводится полный рейтинг из трёх классов с процентами и время обработки
  записи моделью.
- Для всех 50 классов ESC-50 добавлены понятные русские названия. Перевод
  выполняется только на уровне интерфейса, поэтому значения API и модельного
  артефакта не изменяются.

### 2.4. Обработка ошибок

- До отправки браузер проверяет расширение, пустой файл и ограничение 10 МБ.
- Серверная проверка сохранена и остаётся основной, поскольку клиентские
  ограничения можно обойти.
- Ошибки API с кодами 413, 415 и 422 отображаются рядом с формой понятным
  сообщением.
- Добавлена обработка недоступности сервера, неожиданного формата ответа и
  ситуации, когда сервер не вернул ни одного предсказания.
- После ошибки выбранная запись остаётся доступной, поэтому пользователь может
  прослушать её или повторить запрос.

### 2.5. Тесты и документация

- Добавлен автоматический тест корневой страницы и статических ресурсов. Он
  проверяет наличие формы, аудиоплеера, списка результатов, ограничения размера,
  CSS и JavaScript.
- Общее количество автоматических тестов увеличилось с 19 до 20; все 20 тестов
  успешно проходят.
- Ruff не обнаруживает ошибок, а проверка форматирования проходит без изменений.
- Сборка Python-пакета проверена отдельно: HTML-шаблон, CSS и JavaScript входят в
  созданный wheel и не потеряются при установке проекта.
- README дополнен инструкцией запуска и описанием полного сценария работы через
  браузер.

## 3. Полученные результаты

### 3.1. Проверка пользовательского сценария

| Шаг | Ожидаемый результат | Результат проверки |
|---:|---|---|
| 1 | Открытие `http://127.0.0.1:8000` | Страница загружена, модель готова, доступно 50 классов |
| 2 | Выбор поддерживаемого файла | Показаны имя, размер и аудиоплеер |
| 3 | Запуск распознавания | Отправлен запрос в `POST /predict`, отображено состояние обработки |
| 4 | Получение ответа | Показаны основной класс, top-3, уверенности и время модели |
| 5 | Ошибка входного файла | Показано сообщение, интерфейс остаётся готов к следующей попытке |

Для сквозной проверки снова использована запись дождя
`1-17367-A-10.wav`. Работающее приложение вернуло:

| Место | Класс | Уверенность |
|---:|---|---:|
| 1 | `rain` | 0,8350 |
| 2 | `helicopter` | 0,1126 |
| 3 | `door_wood_creaks` | 0,0152 |

Правильный класс отображается как основной результат. После прогрева пять
последовательных запросов обрабатывались моделью в среднем за 19,88 мс. Загрузка
страницы, передача файла и обновление интерфейса в это число не входят.

### 3.2. Итог этапа

Получена первая полностью работающая локальная версия: пользователь может открыть
страницу, выбрать и прослушать запись, запустить ML-классификацию и увидеть три
варианта ответа без использования командной строки или Swagger. Тем самым
выполнена контрольная точка проекта на 26 октября.

## 4. Возникшие проблемы и принятые решения

- Браузерная проверка не может считаться защитой API, поэтому ограничения типа и
  размера файла не переносились из сервера в JavaScript. Интерфейс выполняет
  раннюю проверку для удобства, а сервер независимо повторяет все проверки.
- Выбранный локальный файл нельзя напрямую передать элементу `<audio>`. Для
  прослушивания создаётся временный object URL, который явно освобождается, чтобы
  многократная смена файлов не увеличивала потребление памяти.
- Извлечение признаков остаётся синхронной вычислительной операцией. Как и на
  прошлом этапе, API выполняет её в рабочем потоке, поэтому новая браузерная
  интеграция не блокирует цикл обработки запросов FastAPI.
- Шаблоны и статические файлы должны присутствовать не только в рабочей копии, но
  и в установленном пакете. После добавления интерфейса была собрана тестовая
  версия wheel и проверено наличие всех трёх ресурсов внутри архива.
